# Agent 接口架构

本文件记录现行接口的责任边界和保证。可执行用法以命令树、`linear guide` 和 `linear recipe` 为准；早期计划和一次性交付证据保留在[历史交付记录](agent-interface-delivery.md)与 [Skill 迁移记录](skill-migration-ledger.md)，不能据此推断当前能力或发布状态。

## 工具与上下文的责任

CLI 同时服务终端用户、Agent 和无人值守脚本。用户决定目标和授权；程序提供可发现的操作、机械检查和结果。Linear 保存变化中的问题、证据与决定，代码注释保留必要意图及 Issue 链接，确定性约束进入代码与测试，跨任务稳定事实归入知识库。

一个外部 Linear Skill 负责激活和缺失二进制时的引导。命令、指南与工作流示例随 CLI 分发；运行 Agent 的宿主负责执行授权策略。能力元数据、预览、确认参数、登录成功或凭据存在都不扩大用户授权。

| 事实                                | 权威位置                                                   |
| ----------------------------------- | ---------------------------------------------------------- |
| 命令、参数、别名、单命令验证        | `src/commands/` 和实时 Cliffy 命令树                       |
| 根／领域导航与能力发现              | `src/commands/usage.ts`，从树生成                          |
| 跨命令且随版本变化的操作方法        | `docs/guides/`，由 `src/guides/content.ts` 静态嵌入        |
| 上游字段和有类型约束的 GraphQL 文档 | `graphql/schema.graphql`、源码 `gql`、codegen              |
| 原始依据比较与机器结果              | `src/utils/replacement.ts`、`errors.ts`、`write-result.ts` |
| 共享业务操作与文件关联              | 命令模块导出的操作与 `src/operations/`                     |
| Issue 组合执行、回执和恢复          | `src/delivery/`                                            |
| VCS、GitHub 组合和组织治理策略      | `recipes/` 的说明与脚本，由 `src/recipes/` 静态嵌入        |

命令树定义单命令事实，指南解释多个入口之间的依赖与边界，工作流示例提供可修改的说明和脚本。根导航始终可发现；已知单个命令可以直接调用，不强制先走发现流程。

## 单命令与薄组合层

```text
参数 / 文件 ──→ 有类型约束的共享操作 ──→ GraphQL / 文件传输
                       ↑
                Issue plan / apply

JS / Python ──→ CLI 的 JSON 与文件合同
            └→ 原生 GraphQL 处理复杂读取及长尾能力
```

常见操作留在专用命令：名称解析、领域校验和实际 mutation 由同一实现负责。Issue 的创建、更新、评论、侧栏附件、关系与 `apply` 共用操作函数。`apply` 不组装 argv、不启动子 CLI，也不复制名称解析与写前校验。

只提取真实重复的机制，不建立公共 SDK、全资源反射层、通用交付语言或示例执行器。已有增删改查、小字段读取、上传下载、交互选择和编辑继续保留各自价值。小字段读取只请求需要的字段。

以下责任由可编辑的工作流示例承载：GitHub PR、自动链接、Jujutsu 提交检索、开始工作时的 VCS 编排和健康检查策略。`issue pick` 只选择并输出编号；`team key` 输出可读团队 key。创建项目后关联 Initiative、团队迁移后删除均是显式独立操作。查看入口为 `linear recipe`；源码见[示例目录](../recipes/README.md)。

## 原始依据与替换

Issue、Comment、Project、Initiative、Document、Milestone 的读取使用 `{organization, <API 对象>}`，保留稳定 ID、API 字段名，以及字段缺失与显式值的区别。调用者在讨论或编辑前保存原始读取，直接作为 `--base-file` 输入。非交互入口不能临时读取新值冒充调用者的原始依据；交互编辑在展示旧内容前保存原始读取。

字段替换默认要求依据。显式 `--unprotected` 只跳过原值比较，仍执行身份、字段、文件与领域检查；它不替代 Document 行内评论锚点的独立保护。创建、原生增量与追加不强制不存在的旧值。关系新增检查是否会替换既有关系；标签增删保留上游增量语义。

负责实际 mutation 的操作先完成输入与名称解析，固定 UUID，再进行最后一次读取与比较：额外依赖变化时拒绝；待修改字段的当前值与目标值精确相同则不写，与原始值相同则可写，其余为冲突。一个字段冲突即拒绝整个对象更新；无关字段不比较、不提交。

引用按稳定 ID 比较，明确的 ID 集合按集合语义比较。Markdown 不通过泛化规范化放行覆盖或判为无需写入。服务器可能改写 Markdown；写入确认和读回核验分别报告，不为消除差异重复提交。

这是客户端在提交前进行的最后一次读取与比较：不提供服务器 CAS、锁、事务、exactly-once、ABA 检测或最后读取之后的竞争保护。原始依据的要求及操作示例见 `linear guide automation`。

## 效果、分页与回执

专用写入口使用统一的 `{ok,effect,data,...}` 写入结果。`effect` 为 `none`、`applied` 或 `unknown`，与读回核验 `verification` 分开。参数解析、本地拒绝、认证、GraphQL 与网络失败均通过同一机器输出通道。人类诊断在 stderr，JSON stdout 不混入进度。

复合操作保留已确认效果。上传签名申请、字节传输、创建关联分别处理；关联失败不能抹掉可继续使用的上传回执。没有成功确认时，不从错误或非零退出推断零效果；已确认但回执缺失时保留 applied 并阻止自动重发。

完整分页读到 `hasNextPage: false`，空／循环游标或结构变化显式失败。自动分页只用于 query，原生 `api` 的 mutation 配合 `--paginate` 会在首次请求前被拒绝。GraphQL 部分错误不伪装完整成功；跨页读取不承诺数据库快照。

原生 `api --unprotected` 的 mutation 明示跳过专用领域校验，保留原始 GraphQL 响应；不建立 mutation 到专用命令的第二份目录。它不提供自动重试、回执或执行账本，未知效果由调用者对账。具体例外见 `linear guide graphql`。

## Issue 交付与恢复

交付清单组合已有 Issue 操作；`set` 使用对应命令选项的名称，`base`／`baseFile` 保存原始读取。`plan` 零写入并复用准备逻辑；`apply` 最后重读并调用同一实际写入实现。整批本地材料在首写前读取和校验，上传前检查指纹。

恢复只有 `src/delivery/checkpoint.ts` 一份执行账本实现。派发写入前持久记录 `unknown`，确认并取得回执后记录 `completed`；上传回执独立保存。`completed` 续跑只核验、不重放，`unknown` 阻止所有自动续跑。单命令不强制创建执行账本。

部分成功不回滚，同一交付清单不能并发执行。交付清单和执行账本使用 `schemaVersion: 2`，明确拒绝版本 1。保留旧文件、匹配的旧版本二进制和对账路径，再为明确剩余工作建立独立清单；不自动迁移或删除历史记录后重放。状态、输出路径及核验范围由 `linear guide issue-delivery` 统一说明。

团队迁移示例只保存固定 UUID 范围和逐项结果映射，失败即停；不把 Issue `apply` 扩展为团队生命周期工具，也不建立第二个恢复引擎。健康检查规则保存在普通脚本，严重度和时间阈值属于可修改的组织约定。

## 文档与验证

指南元数据头只含 `name`、`description`、`commands`；`commands` 必须指向现有规范命令。指南与工作流示例通过静态文本导入嵌入二进制，安装后无需源码目录即可离线读取。示例的展示和导出不执行脚本；脚本运行所需的外部工具与依赖由示例说明。测试核对文件、注册、命令引用和编译内容一致，外部 Skill 不重复这些命令事实。

验证覆盖真实生产入口的参数错误、JSON 通道、分页、身份、冲突、部分字段无需写入的更新、部分成功、回执与续跑。故障注入在隔离服务器验证，不将测试替身、构建通过或合并当成线上状态。发布验收另外固定实际编译产物、源码版本与执行证据；发布和安装状态分别报告。维护流程见 [AGENTS.md](../AGENTS.md)。
