# Executable acceptance contract

These tests execute an arbitrary `linear` binary from outside its source tree. They do not import application code, use Deno's test runner, inspect GraphQL operation names generated by the implementation, or replace command actions. Python 3.11 or newer and the standard library are sufficient.

The contract protects observable behavior, rather than help-text spelling or implementation choices. Before extending it, identify the failure to catch and choose an independent oracle:

| Failure                                                                                                     | Oracle                                                                              |
| ----------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| A successful command prints progress into JSON, accepts invalid input, or unexpectedly accesses the network | Exit status, complete stdout/stderr, and the HTTP request log                       |
| A query drops partial data, skips a page, repeats a cursor, or silently truncates results                   | Explicit HTTP response sequences, outgoing variables, and the complete JSON result  |
| A mutation is retried, or a lost response is reported as a known failure                                    | Actual HTTP dispatch count and the public `effect` value                            |
| A write reports success without changing Linear, updates the wrong object, or loses Markdown                | Real Kadoraba objects, checked by independent read-only GraphQL requests            |
| A protected update overwrites a concurrent edit, or delivery replay duplicates a write                      | Real remote state, actual mutation counts, comments, and the saved execution ledger |
| A packaged binary depends on the source checkout                                                            | Bundled guides and recipes read from an isolated working directory                  |

The local HTTP service is a protocol fault injector, not a Linear implementation. It only returns the explicitly supplied response sequence; extra requests fail. It does not invent missing objects or validate business queries. Business acceptance uses the real API. Existing TypeScript tests remain useful developer checks, but do not constitute the language-independent migration gate.

## Run

```bash
mise run test:contract:build
mise run test:contract -- --binary "$PWD/outputs/contract-install/bin/linear" \
  --report outputs/contract-offline.json
```

To test a replacement implementation, pass its executable to the same runner:

```bash
python3 test/contract/run.py --binary /absolute/path/to/replacement-linear \
  --report /absolute/path/to/contract-report.json
```

Offline cases run concurrently with isolated homes, working directories, credentials, and HTTP ports. The binary is compiled once; compilation is not included in case timings. `--jobs 1` gives a sequential comparison; `--filter` selects case names. Reports include subprocess output, HTTP bodies without authentication headers, durations, and behavior coverage derived from the binary's current command tree. Merely discovering a command is not counted as behavioral coverage.

When `--live` is requested, every selected offline case must pass first. A failure preserves the offline report, records `liveSkippedReason: "offline-failures"`, and skips credential prompting and the live phase.

The PR gate also checks eight portable POSIX defective executable wrappers and two Linux lock wrappers: polluted JSON, false success, lost partial data, duplicate mutations, dropped pages, dropped variables, an unknown write reported as having no effect, unexpected GET traffic, bypassing the fixed delivery lock, and opening its file without locking. Each must fail its corresponding production-entry scenario for the intended reason. This proves these specific oracles can detect regressions; it does not prove every possible defect is covered. The wrappers run only against the offline fault service, never Kadoraba.

`--slow` adds real wall-clock body-read deadline checks. The service sends headers and the start of a JSON body, then stalls; query failure and unknown mutation outcome must finish within 65 seconds with one dispatch. These take about a minute and are excluded from the fast PR gate. Include them, together with live business acceptance, when accepting a replacement implementation:

```bash
python3 test/contract/run.py --binary /absolute/path/to/replacement-linear \
  --slow --live --report /absolute/path/to/migration-contract.json
```

```bash
mise run test:contract -- --binary "$PWD/outputs/contract-install/bin/linear" \
  --live --report outputs/contract-live.json
```

Live acceptance requires explicit authorization to manipulate a disposable Kadoraba workspace with at least one existing team and two API-visible users for the pagination success path. Supply only `LINEAR_KADORABA_API_KEY`, or enter the key at the hidden prompt. The runner never reads the host's `LINEAR_API_KEY` or credential files. It verifies workspace identity with the exact target binary before creating objects, retains receipts for cleanup, and checks deletion through independent reads. Issue, Project, Document and Initiative deletion means trashing, not permanent erasure. Comment, Label and Milestone absence is verified separately; arbitrary API errors are not accepted as deletion evidence.

An unmodified forwarding gateway records the CLI's actual requests to Linear; the read-only oracle contacts Linear independently. The suite checks mutation counts as well as remote state, so idempotent operations and rejected writes cannot secretly dispatch mutations. It neither injects faults against the live API nor retries live mutations itself. Nonempty cleanup failures fail the run and remain in its report.

The gateway starts read-only. Both the target binary and the independent oracle must identify Kadoraba and agree on workspace and viewer IDs before mutations are enabled. Each subprocess receives its own temporary gateway endpoint: bounded read commands cannot forward mutations even while concurrent write commands run. Writable commands retain the no-kill behavior, while read commands honor their subprocess deadlines. These controls apply to traffic through the gateway; the executable still receives the experiment credential, so this is not a network sandbox for a malicious binary that contacts Linear directly.

`mise run test:contract:safety -- --binary /absolute/path/to/linear --report outputs/contract-safety.json` checks these driver boundaries offline, including rejected or forged identity, per-command permissions, deadlines, skipping live after offline failure, and missing Orb tools. It uses the real driver and CLI entry points with local HTTP fixtures; only the external live connector is replaced when proving that it is never invoked. PR CI retains this evidence separately from business acceptance.

The live gateway permits one direct root response key per mutation, including aliases and nested fragments. It refuses mutation batches and root fragments before forwarding to Linear because the current suite cannot independently account for and clean every additional write. Accepting a batching implementation requires extending that accounting and cleanup boundary; this guard constrains the experiment, not the CLI's native `api` command.

Delivery acceptance also launches two CLI processes against the same manifest. It requires one remote comment, one actual mutation, nonempty completed execution items with the exact comment receipt, and a retained lock file. Sequential replay of that same concurrent manifest must preserve the saved ledger and produce no further mutation.

Concurrent launch alone does not guarantee lock contention. The Linux offline lock scenario holds the fixed checkpoint lock from another process and observes the target at that exact lock before releasing it. Linux kernel lock waiters prove actual blocking. macOS and Windows do not yet have an equivalent contention oracle; an open descriptor is insufficient evidence, so the strict case and its two canaries are explicitly omitted there. Reading the invalid ledger and returning the expected refusal are permitted only after release. This checks the real CLI's OS boundary without live API fault injection. Git supplies the VCS scenario; the runner adds no Python package dependencies.

Live runs save a credential-free `.live-progress.json` journal beside the report before dedicated `create` calls and after receiving identities. All captured creation receipts, including duplicate writes rejected by request accounting, enter the cleanup inventory. Unresolved creation receipts fail the run and remain in its journal. Cleanup checks the run's unique namespace before deleting through the target CLI. If the process is interrupted, use that journal to reconcile the named objects and any intent with an unknown outcome; do not automatically repeat a creation. The final report also retains exported originals, drafts, and delivery checkpoints after temporary working directories have been removed.

The pagination success path uses an independently-read user catalog. A filtered Issue connection was observed returning an `endCursor` and then rejecting that cursor with `INPUT_ERROR`; the CLI preserved that upstream error and failed. This service observation is retained separately, rather than treated as a CLI regression or made green by accepting incomplete pagination. Protocol cases still require failure on a later-page error.

The report distinguishes offline protocol coverage and live business coverage. A green offline run alone cannot certify a rewrite. Live API drift is reported as a failing observation, not accommodated by silently changing expectations. Authentication/keyring integration, browser/editor interaction, platform-specific packaging, uploads and download authorization, and every flag combination are not yet covered by this contract. Continue running the existing checks for those boundaries until executable scenarios replace them.
